# Lumen Cognitive Fusion Architecture

## Stack

1. Local/provider-independent intelligence
2. Unreal/MCP perception
3. Persistent world model
4. Episodic and procedural experience memory
5. Capability-gap graph
6. Research and evidence retention
7. Hypothesis generation
8. Isolated experiment/evolution path
9. Tool-foundry candidates
10. Temporal learning with a CPU fallback
11. Quantum-inspired optimization with a classical fallback
12. Evolution governor with test, benchmark and rollback gates
13. Persistent anti-repetition progress controller
14. Continuous reassessment

## Unified loop

OBJECTIVE -> AUDIT -> GAP -> RESEARCH -> LEARN -> HYPOTHESIS -> EXPERIMENT -> TOOL/CODE -> TEST -> VALIDATE -> BENCHMARK -> SAFETY -> PROMOTE -> MONITOR -> EXPERIENCE -> NEXT GAP

Failure path: FAIL -> DIAGNOSE -> RESEARCH -> CORRECT -> RETEST

The fusion layer is a control plane. It does not bypass existing F12-F32
experiment, security, rollback or promotion gates.

## Optional research backends

External scientific backends are optional. The core remains dependency-light
and CPU compatible. Future adapters can attach without changing the planner
contract.

## Persistence

The progress controller persists evidence and anti-repeat state. Cognitive
fusion snapshots persist world facts, capability gaps, research findings,
tool candidates, hypotheses, lessons and temporal predictions.

## Invariant

Research, memory, optimization and generated tool candidates may propose
improvements. Only the governed evolution pipeline may make executable changes
live.
